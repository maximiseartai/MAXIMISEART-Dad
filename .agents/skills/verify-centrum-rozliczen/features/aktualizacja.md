# Aktualizacja narzędzia

On Konfiguracja, the card `Narzędzie` shows the tool's version, its commit
and the day the tool moved to it, and whether it is the newest (`Aktualna`, `Jest nowsza wersja`, `Nie
sprawdzono`). The card offers `Zaktualizuj narzędzie` only when there is a Wydanie newer than
the tool (`update_offered`, ADR 0014): not when it is current and not without GitHub's answer. The same
button sits in the Diagnoza (`aktualnosc-i-onedrive.md`) and in the card of the
Powiadomienie o nowej wersji (`powiadomienia.md`); there is one
update per Centrum, so while it runs every such button is disabled. Dad clicks
it: the page shows the step while Centrum fetches `main` with the Wydania and moves the tool's
clone forward. When the new
version changes `requirements.txt`, the card shows `Instalowanie bibliotek…`; a
failed installation moves the clone back and the card shows the Komunikat. After
a successful update Centrum closes itself, the restart guardian starts the new
version on the same port, and the tab waits, reloads by itself, and briefly
shows `Zaktualizowano`; a Wydanie the update does not take (a tag that never was the tip of
`main`, ADR 0014) gives `Masz najnowszą wersję.` During
the update a second update and closing Centrum are refused. Without internet
the card shows the Komunikat in three parts („brak połączenia z GitHubem”) with
`Wyślij do Maksa` and its preview, the tool stays as it was, and a second click
once the internet is back updates it. A new version whose Centrum does not
start goes back by itself: the restart guardian moves the clone back and starts
the old version, and the tab reloads on it with the Komunikat „Nowa wersja
narzędzia nie wystartowała.” under the title of whichever page it lands on; a tab opened later, by the
shortcut, shows it on Okresy too, until Dad clicks `Zaktualizuj narzędzie` again.
When the old version finds „ok” in the guardian's result file (the disk refused
the guardian both the removal of „ok” and the write of the failure), it shows
the Komunikat of an unexpected failure, not „Narzędzie zaktualizowane”, because
the commit it runs is not the one „ok” names (#490). A result the Centrum log
already has does not come back on a later start (#491). A failure in the
result file whose commit before the update is not the commit Centrum runs is
old: the log gets `aktualizacja-wynik-stary` and the card says nothing, so
when the disk lets the guardian neither remove the file of
`NOWA_WERSJA_NIE_WYSTARTOWALA` from A to B nor write „ok” after Dad's next
click, B, which answers, shows no failure (#725).
A Centrum log that cannot be read lets the result through. The drive checks
none of this: the rules are checked by `tests/test_centrum_aktualizacja.py`
and the model of `verify-aktualizacja-narzedzia`.
Konfiguracja keeps GitHub's answer about the newest Wydanie (one answer shared with
Powiadomienia) for 10 minutes of Centrum's clock, so each harness change of the Wydanie also moves that clock on. In this run the tool
is the fixture's synthetic clone with a local "origin", and its Centrum is the
run's scripted Centrum, so the restarted Centrum keeps the run-local
boundaries; the verification never touches the checkout it runs from and never
reaches GitHub.

## Sub-features

- `aktualizacja-jest-nowsza`: with the newest Wydanie one commit ahead, the card shows the clone's commit, `Jest nowsza wersja` and `Zaktualizuj narzędzie` (`update_offered` `true`), and no update has run.
- `aktualizacja-brak-sieci`: without internet the click ends in the Komunikat `Nie zaktualizowano narzędzia: brak połączenia z GitHubem.` in three parts, `Zaktualizuj narzędzie` as the main action and `Wyślij do Maksa` beside it; the preview `Co zostanie wysłane` has the code, the commit before and the libraries flag from the log; the clone and Dad's files are unchanged, and the log has the failed update with its code. Once Konfiguracja's memory of GitHub's answer runs out, still without internet, the card shows `Nie sprawdzono` and no `Zaktualizuj narzędzie` (`update_offered` `false`), with the failed update's Komunikat still in it.
- `aktualizacja-postep`: with the internet back, a double click (the retry) starts one update; the card shows `Pobieranie nowej wersji…` with the button disabled, and a second update and closing Centrum are refused with 409.
- `aktualizacja-ponowny-start`: after the update the old Centrum closes itself (`zamkniecie z=aktualizacja`) and stops answering; the card shows `Ponowne uruchamianie Centrum…` with the button disabled.
- `aktualizacja-zaktualizowano`: without any click the tab reloads on a new Centrum (other `instance`, the new `commit` in `health`), still on Konfiguracja, and shows the notification `Zaktualizowano` with the new commit from `health`; the card shows the new commit, since the day of the update, as `Aktualna` without `Zaktualizuj narzędzie` (`update_offered` `false`), the clone stands on the origin's newest commit, the guardian's result file is gone, Dad's files in the clone's `config/` (his changed konfiguracja wykonawców, which the new commit stops tracking, among them) and the run's configuration directory are untouched, and the Centrum log has the start and the end with both commits and no path, the end written by the new Centrum before its `start`.
- `aktualizacja-najnowsza`: the scripted GitHub names a Wydanie the update does not take (a tag that never was the tip of `main`, ADR 0014), so the card shows `Jest nowsza wersja` with its button; the click says `Masz najnowszą wersję.` and leaves the clone where it is.
- `aktualizacja-instalowanie`: with the newest Wydanie on a version that needs a new library, the card offers its button without the earlier `Masz najnowszą wersję.` (the server reports `idle`), then shows `Instalowanie bibliotek…` with the button disabled, and the server reports the step `installing`.
- `aktualizacja-instalacja-nieudana`: pip cannot install the library offline; the card shows the three-part Komunikat `Nie udało się zainstalować bibliotek nowej wersji narzędzia.`, the clone is back on the commit before the click with Dad's files untouched, and the log has `wynik=INSTALACJA_BIBLIOTEK` with both commits and `biblioteki=tak`.
- `aktualizacja-nie-wystartowala-ponowny-start`: with the newest Wydanie on a version whose Centrum does not start, the click on Konfiguracja ends with the old Centrum closed and `Ponowne uruchamianie Centrum…`; Dad goes to Uruchomienia while it restarts.
- `aktualizacja-nie-wystartowala`: without any click the tab reloads on the old version (other `instance`, the old `commit`), still on Uruchomienia, which has no button of its own, and shows under the title the three-part Komunikat `Nowa wersja narzędzia nie wystartowała.` with `Wyślij do Maksa` as the main action and no `Zaktualizowano`; on Konfiguracja the same Komunikat stands once, under the title, not in the card; the clone is back on the commit before the click with Dad's files untouched, and the log has `wynik=NOWA_WERSJA_NIE_WYSTARTOWALA` with both commits, written by the old version before its `start`.
- `aktualizacja-start-ze-skrotu`: Dad closed the browser while Centrum restarted and starts it from the shortcut; the new tab, which the restart did not reload, lands on Okresy with the same three-part Komunikat `Nowa wersja narzędzia nie wystartowała.` once under the title and `Wyślij do Maksa` as the main action.
- `aktualizacja-ok-przy-starej-wersji`: one more click on the version that does not start, and the disk refuses the guardian both the removal of „ok” and the write of the failure (harness); the tab reloads on the old version, still on Konfiguracja, with the three-part Komunikat `Nie udało się zaktualizować narzędzia z nieoczekiwanego powodu.` under the title, „jeszcze raz” and `Wyślij do Maksa`, and no `Zaktualizowano`; the card shows the old commit with `Jest nowsza wersja`; the log has `wynik=NIEOCZEKIWANY_BLAD` with both commits.

## How to get to it (user POV)

- Sidebar `Konfiguracja` (`#/konfiguracja`), card `Narzędzie`, button `Zaktualizuj narzędzie`.
- Powiadomienia (`#/powiadomienia`), the card `Nowa wersja <x.y.z>` above the list, button `Zaktualizuj narzędzie` (`powiadomienia.md`).
- Uruchomienia, region `Diagnoza`: in the explanation `Jest nowsza wersja narzędzia.` or in the note `Propozycja aktualizacji`, button `Zaktualizuj narzędzie`.

## Gotchas

- The progress screenshots are `live`: the spinner turns until the update ends, so waiting for every animation would time out; the drive waits only for the status's own entrance.
- `main-commit.txt` must go when the feature ends: later features expect `main` to be the tool's own commit. After the update the clone's `HEAD` is the new commit, so leaving the file would still read as current, but it would mask a feature that pins another `main`.
- The clone is moved by real Git on this machine. Its user configuration applies to the update; the fixture's own commits ignore it.
- Pip is the production installer (this Python's `-m pip`) with `PIP_NO_INDEX=1` set by `serve_centrum.py`, so it never reaches PyPI. A virtual environment made by `uv` has no pip; then `-m pip` fails at once, which is the same failed installation for Dad.
- The installing screenshot is `live` for the same reason as the progress one.
- The restarted Centrum is a new process started by the restart guardian, not by the runner: `server.txt` holds only the first server's console, the new server rewrites `server.json` with its pid, and cleanup stops that one. In `all`, every later feature drives the restarted Centrum.
- The restart screenshot is `live` and needs the restart pacing: without it the new Centrum answers within about a second.
- The result `Masz najnowszą wersję.` is about the newest Wydanie Centrum knew when the update ended: once Centrum knows another one (Konfiguracja, Powiadomienia and Diagnoza share one answer from GitHub), `GET /api/tool-update` is `idle` and the card drops the status (issue #373). `Installing` checks that with a newer Wydanie, and `Up to date again` with the tool's own commit as the newest Wydanie.
- The version that does not start is only a `run_centrum.py` that fails at once; the real launcher's start failure without a dialog (`--bez-okienek`) is covered by `tests/test_opiekun_ponownego_startu.py`.
