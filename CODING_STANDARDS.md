# Coding Standards

Rules for writing and reviewing code and tests in a repository where agents write every line.
A check's message (a test assertion, the `msg` of a `banned-api` entry, a refusal of a hook or tool) states its rule and the fix.
A rule that a check enforces sits in its section's table, one row per rule, beside the check that guards it, only when the check's message does not already say it or the check misses forms that review must catch; the reviewer does not repeat a check, and a row whose mistake can no longer happen is deleted.
Code and test rules sit in this file, in English, and process rules in [`docs/agents/pr-i-ci.md`](docs/agents/pr-i-ci.md) or [`docs/agents/skille.md`](docs/agents/skille.md).
A form that a new or changed check is known to let through is a sample in `ZNANE_LUKI` of the check's test, named by the class of the mechanism that lets it through (it knows only the imported name, it reads no import or command built at run time, it trusts ruff and mypy suppressions, reflection by attribute name); `tests/fixtures/znane_luki.py` runs it through the check's real mechanisms (ruff, mypy, the check itself) and fails, asking to remove the sample, once the check catches it, and the row of that check, when it has one, points to this test.
The samples are the gaps known so far, not a full list of forms or of classes, so no row, docstring or PR body calls them complete, and a newly found gap becomes a new sample or is closed by a construction (a type, a ruff ban, a refusal at run time).
A check that promises a whole class (it catches every form of a call, a field carries only X, nothing of Dad's data passes) states that promise as a table of cases, which is a parametrized test of the check with one `pytest.param` and an `id` naming each case: each form it catches with an example, and each boundary form that passes it; the PR that adds or changes the check writes the cases before the code and shows them in `## Evidence`, because a PR that started from code met a new case in each review round (#925: three FAIL, then #941 with the table passed in its first round; #917).
A boundary of a check stands as a case of its test (a sample in `ZNANE_LUKI` or a `pytest.param` with an `id`), and in prose only in the check's row after `boundary:` when no test can run it (`grep -n "(boundary[:]" CODING_STANDARDS.md` lists them), like the rules of `npm run rules` in the section Frontend, whose dependencies the pytest jobs that run the samples do not install; a boundary that a docstring or comment still keeps moves to a case or to the row with the next change of that check ([ADR 0043](docs/adr/0043-kod-bez-komentarzy.md)).
Owner right („prawo właściciela”) is the lasting use of a banned API by the module that the ban's message sends the rest of the code to, and it sits only in the rule's configuration, which the diff of the rule shows (for `TID251`: `per-file-ignores` in `ruff.toml` and `OWNERS` in `tests/test_zakazy_ruff.py`; for an ast-grep rule: its `ignores:`), never in a comment: no `noqa` hides a `TID251` or an `import *` ([ADR 0036](docs/adr/0036-chwast-to-regula.md), `tests/test_zapadki.py::test_zadna_linia_repo_nie_tlumi_zakazu_ruff`) and no Python file, where the ast-grep rules look, contains the text `ast-grep-ignore` at all, also in a string, so a sample or a message builds it from `odpalenia_ast_grep.SUPPRESSION` (`tests/test_zapadki.py::test_zadna_linia_repo_nie_tlumi_reguly_ast_grep`).
A change of an ast-grep rule (its file, `files:`, `ignores:` or `sgconfig.yml`) applies from its own merge: the base's rules also judge the lines a PR adds, a directive text in an added line is reported too, and every case in `metadata.przypadki` of the base's rules is still listed and caught by some rule after the merge, whatever its id or file (condition 6 of `tools/scal_pr.py`, also in the status „Werdykt i bramka”), so a PR that removes or narrows a rule lands before the code that needs it.
A temporary exception („wyjątek tymczasowy”) sits on the line it covers, with its reason and a deadline, the PR body says why the check cannot be fixed now, and the reviewer checks that reason; Maks's consent stands beside it only when the reason is a decision of his kind in [`docs/agents/issue-tracker.md`](docs/agents/issue-tracker.md), „Decisions for Maks” (pattern: `KNOWN` and `known()` in `tests/fixtures/fakt_domeny.py`, a risk to Dad's data that Maks accepted).
A bullet is a judgement call that no check makes: the reviewer reports a broken bullet as Drobne, and as Ważne only with the behaviour defect it causes, proved as the skill [`przeglad`](.agents/skills/przeglad/SKILL.md) asks.

## Fixing a Mistake Class

A mistake is a class once it has happened twice: two review findings, two red runs, or a correction from Maks that repeats an earlier one.
Fix a class at the highest rung that works of the ladder (a)–(e) in [`korzen.md`](.agents/skills/przeglad/korzen.md) of the skill `przeglad`, which also says what the PR writes about each higher rung and what a structure rule gets when no type, ruff ban, import-linter contract or ast-grep rule expresses it.
Turn a ruff or mypy rule on when it has no violation left, like the rules under `# Zapadki` in `ruff.toml`.
Rung (d) is a declarative rule of a ready tool: an ast-grep rule in `reguly-ast-grep/`, run on the lines a change adds, with a message that says what to use instead, bad and good samples, the forms it misses as samples in `ZNANE_LUKI_<RULE>`, the proof of `tools/na_scalonych_pr.py`, and the case it was made for in its `metadata.przypadki` (the Ważne `PR/W<n>/r<k>`, or `<full SHA> file:line` of the commit that added the mistake), which CI runs with `tools/na_scalonych_pr.py --przypadki-regul`; a new check that matches lines with a regular expression is not a rung.
Only the rules on the list `REGULY_CALEGO_DRZEWA` in `tests/test_zapadki.py` also run on every line of their files: a rule that replaces a ratchet joins the list in the same PR, because the ratchet ran on the whole tree, and any other rule may join it in a PR that shows the rule reports no line of its files, like `komentarz-w-src` and `historia-w-docstringu` after the series #1616.
A ratchet becomes a rule only when the rule reads the mechanism without a list of node kinds, the differential comparison of the ratchet and the rule uses a corpus independent of the rule, and the rule keeps the whole-tree run the ratchet had.
Two ratchets in `tests/test_zapadki.py` stay regular expressions.
The navigation ratchet stays because a tree rule loses two of its forms, both samples of the ratchet: a receiver above the call that gets a value computed from the response instead of the response, and `expect_navigation` passed to another call in a `with` without `as`.
The parser ratchet (`PARSERS`) stays because a tree rule's exemption would be the same list of files in `ignores:`, outside owner right, and the list grows only with a reason in the PR body why a ruff or ast-grep rule or a behaviour test is not enough, which the reviewer checks (#1888).
A new check fails on the commit of the PR whose review found the mistake, raises no false alarm on the recent merged PRs of `tools/na_scalonych_pr.py --ostatnie` (`CHECK_PRS` of that tool, one of them with Windows-only code; a rule's proof uses its `RULE_PRS` and `FALSE_ALARMS`), and the PR body shows both runs (skill `pr`).
Fix the class, not the instance: when a review finds one case, look for every case of the same fault in the change and in the repository, and fix them together.
When a fix of a rule keeps growing a list of exceptions, replace the list with the shape the code accepts.

## Domain Language

- Name tests after the domain behaviour they protect, in the terms of `GLOSSARY.md`.
  Use an implementation name only when the test intentionally protects that module's interface.
- A `GLOSSARY.md` entry defines its term, carries the domain motivation that code cannot state, and, for implementation detail (which host does what, from which file), names the code owner that states it, like `settings_at_start.SettingsAtStart` in „Ustawienia ze startu”, instead of restating it.
  Other code reaches that owner by calling or importing it and never restates its rule, because a restatement can drift from its owner without anything failing (#2069 r2: the entry and the docstring it restated said opposite things about where the replay takes the same setting).
- Write identifiers in `src/` in English, naming a defined term by its name in the `identyfikator` column of `GLOSSARY.md`, and test names, case ids and every text tata or Maks reads in Polish, with the terms of `GLOSSARY.md` and no synonym of a defined term.

## Design

- Give each decision one owner: a rule, a limit or a mapping lives in one module, and every caller asks that module instead of keeping its own copy, which drifts.
- Keep a coordinator responsible for sequencing, not for the details of the workbook it coordinates.
- A module with one main operation exposes that operation as its seam and keeps layout constants and helper functions private, so callers do not know how a workbook is loaded, repaired, or saved atomically.
- Model a domain variation as data: a new case is a new member of an Enum, a row of a table or a variant of a union, not one more branch in an `if` chain repeated across files.
- Read text the program did not write (a shell command, Markdown, HTML, a cell of Dad's file) with a real parser or the tool that owns the format, such as `gh api markdown` for GitHub Markdown, and accept only the forms the code lists: an unknown form fails closed.
  Hand-written parsers that grew by listing bad forms failed review 15 times on 7 PRs in October 2026 (#496, #624, #636, #648).
- A gate or a checker passes only on the result it expects: it lists the units it must see, and a missing unit, a crash or any other outcome is a failure (#445, #479, #554, #667).
- A best-effort step (a cleanup, a kill with a deadline, a notification) returns and records its failure, and never raises into its caller (#447, fixed in #458).
- A Centrum rozliczeń feature that is switched off (its start date or setting missing) leaves no trace: no Centrum log entry and no file in `config/`, because tests and the `verify-centrum-rozliczen` drive check that both stay untouched (#1372, #1375).
- When a change adds a new way to do something, it moves every caller to it and deletes the old way.

## Error Ownership

- Workbook code (`workbook_files`, `template_file`) raises `WorkbookError`, and the catalog of the process that called it translates the error into a Komunikat.
  The files that Sprawdzanie reads go through `input_checks`, which translates their reader errors once for both processes, the Diagnoza and the Konfiguracja; the Rejestr zleceń of the Przygotowanie goes through `preparation_register`, which reads it once for the Sprawdzanie, the Odczyt danych and the Diagnoza.
  A catalog gives `workbook_messages.unusable` a `WorkbookMessages`, one Komunikat for each `Problem`, so a new `Problem` is a new field that mypy asks of every catalog, and the one `match` on `Problem` ends with `assert_never`.
  The sentences about Dad's file open in Excel, its Excel lock file `~$…` and a file OneDrive has not handed over come only from `workbook_messages`.
  Other code calls its catalog's factories directly, and a process summary reports its problems as warning Komunikaty in `warnings`.
- A failure that can invalidate a workbook write, reading or restoring `xl/externalLinks/*` included, raises `WorkbookSaveError` with its `SaveProblem` (`workbook_save.py`), not a generic error.
- Preserve `Nienadpisywanie`: existing input data is reported and never replaced automatically.
- Pass `check=True` to `subprocess.run` unless the code after it reads `returncode`, and never write `check=False` only to silence ruff's PLW1510.

## Test Surface

- Judge a test by two edits: break the behaviour it names and it fails, restructure the internals with the same observable result and it passes.
  Take the expected value from `GLOSSARY.md`, the ADR or the requirement, never from a run of the code under test.
- Test each process through its operation (`run_settlements()`, `prepare_collective_file()`, `order_register()`).
  Give a module with one entry point (one operation or the HTTP API of Centrum rozliczeń) its own tests only for behaviour that entry point cannot reach.
- A module whose interface at least two entry points call (two processes, or a process and Centrum rozliczeń) is a seam: test its rule matrix once, on its interface.
  Each entry point that uses it has one translation test (module error → that entry point's Komunikat) and does not repeat the matrix.
- Test a decision of Wycena w efenix (the execution date, Wycena Emmetta, the completion to the file, the checks of an order, a new Uruchomienie after Dad's change) through the Uruchomienie procesu on the window in process (`_run_in_process` in `tests/test_wycena_efenix.py`, `tests/fixtures/okno_w_procesie.py`), without a browser.
  Keep in Chromium on the Atrapa efenix what only the browser window shows (the page and its build, a failure, a closed window, login, pace) and a few decision runs as smoke tests.
  The window contract in `tests/test_atrapa_efenix.py` shows that both windows give the same run only on its rows, so a new branch of the window in process gets its row there.
- Test Centrum rozliczeń through its HTTP API, the way the browser sees it: responses, the event stream, files on disk, metrics records.
  Prove UI behaviour in the browser with `verify-centrum-rozliczen`, not with component unit tests.
- Make the Rejestr zleceń or a Wzorzec fail in a test through a failing adapter, not by patching a module attribute: the byte source of Dad's files (`DadFiles.source`, in Centrum `create_app(source=...)`) for the Rejestr, the Sprawdzanie of a Wzorzec (`run_context.TemplateCheck`, in Centrum `create_app(template_check=...)`) for a Wzorzec.
  The same adapters reach the Uruchomienie procesu, the Diagnoza and the Konfiguracja, so the fault reaches all three.
- Use synthetic workbook fixtures only, shaped like Dad's real file in what the code reads (a row's style, a merged cell, the format Excel shows), not only in its values.
  Cover both successful and failure paths for each operation's behaviour matrix.
- The test that owns a workbook write verifies every column the write touches (`A:AT` for the Rozliczenie pracownika), preserved formulas and formatting, atomic replacement, and every entry under `xl/externalLinks/*`.
  Other tests assert only the behaviour they name.
- Before a change runs on real files, run the Przygotowanie pliku zbiorczego and the Przebieg rozliczeń as `Podgląd bez zapisu`; Uporządkowanie INTERMAX has no preview and saves a Kopia INTERMAX before it replaces the file.
- Keep tests free of client addresses, order numbers, and row contents in output or logs.
  The one exception is the Zatrzymanie about gaps in `SKUTECZNE` (`ZLE_SKUTECZNE`, ADR 0004): its tests use synthetic `SKUTECZNE` values, because the Komunikat shows the exact cell content.
- Name a file that a test reads or runs with a literal path (`ROOT / "docs" / "adr"`), not a path built from a variable.
  `tools/szybko.py` selects tests from imports and such literals, so a path built at run time hides the dependency.
- Test a rule that matches text from Dad's files (a word or phrase in `URZĄDZENIA` or `CZYNNOŚCI`, an operator name, a period token) with a Hypothesis property, not only with examples: the text anywhere in the cell, glued to punctuation, in any letter case and with Polish letters, two words of the rule in one cell, and the word inside a longer word.

## Documents and Claims

- `--help`, an ADR, `SKILL.md`, a document and a docstring that still stands state what the code does now, and only what a check or a run shows: a number names the run or the command it came from. In code it names the command or tool of the repository that gives it, and the issue or PR of the run goes in the PR body, so a number no command of the repository gives stays out of the code.
- Code gets no new comment or docstring beyond the forms below and the text a program reads (next bullet) ([ADR 0043](docs/adr/0043-kod-bez-komentarzy.md)): what a comment would say goes to a name, a type, a test that fails without the code or a rule (the ladder in [`korzen.md`](.agents/skills/przeglad/korzen.md) of the skill `przeglad`), and what code cannot say goes to an ADR (a decision), `GLOSSARY.md` (domain motivation) or the PR body (the history of a change), never only to an issue, which closes.
  The only comments are a tool directive in its present form (`# noqa: CODE - reason`, `# type: ignore[code]`, `// @ts-expect-error reason`, `// oxlint-disable-next-line rule -- reason`), `// SAFETY: reason`, a shebang and a limit of the outside world as `# ZEWNĘTRZNE: fact (source)`; no comment links an issue.
- Text a program reads (`--help`, the tool list in `AGENTS.md`, rules another tool prints) lives in a named constant, not in `__doc__`, because a removed docstring breaks it silently and a removed constant fails mypy; until the program reads it from a constant, it stays in the docstring that `--help`, the tool list or the digest of a `verify-*` model reads, also for a new tool.
- A change that makes a sentence of `AGENTS.md`, this file, `GLOSSARY.md`, a skill or an ADR untrue fixes that sentence in the same change.
